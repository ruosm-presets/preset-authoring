# Spec: `preset-authoring` — скилл для генерации пунктов JOSM-заготовок AI-агентами

Статус: черновик на ревью
Дата: 2026-10-07

## Проблема

Добавление бренда в пресет `literan-moscow` требует знания десятка конвенций
(CONTRIBUTING.md), ручного исследования бренда (Wikidata, сайт, соцсети),
подбора иконки по строгому формату и прогона проверок. Контрибьюторы без
контекста репозитория ошибаются в сортировке, порядке атрибутов и иконках.
AI-агент может вести этот процесс целиком, но ему нужен системный промпт —
при этом сам пресет-репозиторий не должен тащить AI-обвязку.

## Решение

Отдельный публичный репозиторий `preset-authoring` со скиллом для opencode
(совместим по формату и с другими агентами, читающими SKILL.md). Скилл
ведёт агента от имени бренда до готового закоммиченного `<item>` в клоне
`literan-moscow`, а также обновляет существующие пункты (ребрендинги,
мёртвые ссылки, изменившиеся контакты). Пресет-репозиторий не получает ни
одного нового файла, кроме абзаца в CONTRIBUTING.md со ссылкой.

## Аудитория и установка

- Контрибьюторы ruosm-presets, использующие opencode (или совместимые агенты).
- Установка: `git clone` куда угодно + одна строка в глобальном конфиге:

```jsonc
// ~/.config/opencode/opencode.json
{
  "skills": { "paths": ["~/Dev/preset-authoring/.opencode/skills"] }
}
```

- README репозитория объясняет установку и перезапуск opencode
  (конфиг не горячо перезагружается).

## Структура репозитория

```
README.md                       # назначение + установка
docs/spec.md                    # этот документ
.opencode/skills/add-brand-preset/
  SKILL.md                      # ядро скилла (анатомия opencode-skill-creator)
  references/
    conventions.md              # выжимка правил literan-moscow
    item-template.md            # скелет <item> с плейсхолдерами
    icon-pipeline.md            # конвейер иконок (реюз → Twemoji → Pages URL)
    update-playbook.md          # методология обновления существующих пунктов
```

## Скилл `add-brand-preset`

### Триггер

`description`: «Use when adding a brand/shop chain POI item to a JOSM tagging
preset XML (literan-moscow / ruosm-presets), or updating an existing item
(rebrand, dead links, changed contacts): research the brand, pick tags and
icon, insert or update the <item>, run checks. Triggers: добавь бренд в
пресет, обнови пункт пресета, add brand to preset, update preset item, new
shop item».

### Вход

Пользователь называет бренд (и, опционально, город/контекст). Дальше скилл
ведёт процесс и задаёт вопросы по одному.

### Процесс (6 шагов)

1. **Исследование бренда.** Wikidata API (лейбл ru/en, P856 сайт, P576 дата
   закрытия, поисковые синонимы); сайт бренда (найти страницу адресов —
   обычно в навигации «Магазины/Адреса/Карта»); соцсети (vk/ok/telegram из
   футера). Проверка гипотез через curl с браузерным UA; помнить про
   гео/бот-блоки (401/403/498 ≠ мёртвый сайт). Если сеть закрылась или
   ребренднулась — остановиться и доложить человеку (пример-прецеденты:
   Subway→SUBJOY, банкротство «Связного»).
2. **Данные пункта.** Заполнить шаблон: amenity/shop/cuisine, brand, name +
   ru.name (латиница/кириллица по правилам), контакты (только проверенные
   факты — никаких выдуманных телефонов), wikidata если объект существует,
   часы работы как values-комбо из шаблонов чанков.
3. **Иконка.** Сначала реюз существующего файла из pics/icons/ (подбор по
   смыслу, список — `ls pics/icons/`); если нет подходящего — Twemoji по
   кодопоинту, имя snake_case, загрузка в pics/icons/, URL Pages
   (https://ruosm-presets.github.io/literan-moscow/pics/icons/<name>.svg).
   Формат имени и хостинг только наши — см. icon-pipeline.md.
4. **Вставка.** Найти группу; позиция по сортировке CONTRIBUTING (числа →
   латиница → кириллица, внутри — алфавит; при наличии ru.name сортировка по
   нему). Собрать `<item>` по шаблону item-template.md; порядок атрибутов:
   key/ref → text/name → ru.text/ru.name → values → ru.display_values →
   default → type → preset_name_label → name_context → icon (последний).
   Максимум переиспользования чанков; порядок полей экранной формы как во
   встроенных заготовках JOSM.
5. **Верификация.** В клоне literan-moscow: `python3 scripts/check_presets.py
   --no-http russian_shops.xml` (0 ошибок) + `xmllint --schema` при наличии
   xmllint. Все падения чекера — исправить до коммита.
6. **Коммит.** Только по явному слову пользователя. Сообщение — одну строку,
   стиль репозитория (см. git log). Версию пресета не трогать — инкрементит CI.

### Режим обновления (update)

Триггеры: CI-ворнинг по ссылке пункта, ребрендинг сети, изменившиеся
контакты/часы/иконка, просьба пользователя «обнови пункт X».

1. **Найти пункт**: группа + name (уникальность внутри группы гарантирована
   чекером); прочитать текущие теги целиком.
2. **Исследование** как в шаге 1 основного процесса; методология различения
   «мёртвый» vs «бот-блок» vs «переезд» — в references/update-playbook.md
   (обезличенные паттерны: ребрендинг сети, закрытие сети, soft-404).
3. **Минимальный диф**: менять только подтверждённые факты (ссылка, бренд,
   контакты, иконка); стиль и сортировку не трогать, если они не сломаны.
   Ребрендинг = переименование пункта + brand + ссылка (+ иконка при
   необходимости), с удалением устаревшего brand:wikidata, если у нового
   бренда нет QID.
4. **Верификация и коммит** — шаги 5-6 основного процесса.

Удаление пунктов (сеть закрылась) — всегда эскалация к человеку, агент
сам не удаляет.

### Guardrails (жёсткие правила)

- PII в пресет, тесты и коммиты не попадает никогда.
- Мёртвый/сомнительный бренд → вопрос человеку, пункт не удалять самому.
- Не выдумывать данные (телефоны, wikidata, часы) — только из источников.
- Скилл не модифицирует CI, чанк-инфраструктуру и чужие пункты без запроса.
- Изменения только в клоне literan-moscow; push — только по слову.

## Референс-файлы

- `conventions.md` — выжимка CONTRIBUTING.md: порядок полей, сортировка,
  комментарии/отступы/пробелы, язык (en основной, ru.* дубли), работа с
  чанками. Не копия, а операциональная выжимка для агента.
- `item-template.md` — скелет `<item>` с плейсхолдерами `{{brand}}`,
  `{{wikidata}}` и т.п., построчные комментарии зачем каждая секция; примеры
  «хорошего» item (реюз чанков) и «плохого» (всё инлайн).
- `icon-pipeline.md` — конвейер иконок: реюз → подбор эмодзи → Twemoji CDN →
  snake_case имя → pics/icons/ → Pages URL; формат имён
  `^[a-z0-9_]+\.(svg|png)$` (это проверяет чекер).

## Интеграция с literan-moscow

Один абзац в CONTRIBUTING.md: «Есть AI-скилл для добавления брендов:
ruosm-presets/preset-authoring». Больше ничего.

## Acceptance-тесты

1. Прогон скилла на незнакомом живом бренде → пункт вставлен в правильную
   группу и позицию, чекер зелёный, диф чистый.
2. Прогон на бренде с мёртвым сайтом → агент остановился и спросил.
3. Прогон с иконкой, которой нет в pics/icons → файл добавлен с корректным
   именем, URL валиден.
4. Установка с нуля по README → скилл виден в opencode после перезапуска.
5. Режим обновления на пункте с переехавшей ссылкой → ссылка заменена,
   остальное не тронуто, чекер зелёный.

## Out of scope

- Генерация новых пресетов с нуля (отдельная задача).
- Удаление пунктов без явного решения человека.
- Скрипты/код в этом репозитории (весь executable-функционал живёт в
  literan-moscow/scripts/check_presets.py).
- Поддержка других harness'ов кроме формата SKILL.md (файл останется
  обычным markdown — другие агенты смогут читать его как документ).
